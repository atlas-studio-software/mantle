## Notes for the port
- Every page is drawn with the Settings kit only (toggle / choice / slider / text / number / list / status / button with the admin shield). The only non-kit drawing in scope is the Display arrangement map (absolutely positioned boxes in a 360 x 120 area, not draggable) and the Accessibility text-size preview row (inline font-size). Nothing in these pages is WebView-only; no page needs a WebView2 fallback. Drag-to-arrange on the map or a VU bar for the mic test would be NEW behaviour, not parity (the mic level is text "N%").
- Write protocol shared by all pages (`_devices-bridge.js write()`): in a test run every write is a sidecar dryRun whose "Test run, nothing changed: ..." note springs the control back. Live, a sidecar `needsAdmin` answer becomes ONE UAC prompt through the elevation broker (sidecar/ELEVATE.md); a declined prompt springs the control back with "You said no to the administrator prompt; nothing changed". The native port needs the same test-mode switch or no page test can run safely.
- Display keep-or-revert is owned by the SIDECAR (SysDisplay.cs Arm/Finish, 15 s default, ProcessExit hook). The page only renders the countdown (250 ms poll) from the change reply, `sysdisplay.get` `pending` and the display events; it must not run its own revert timer. Keep the token guards and the match on "no display change is waiting".
- Display extras: night light schedule/strength edit an undocumented CloudStore binary blob (hours 01-23 only, no minutes or midnight). Scale uses undocumented DisplayConfigGet/SetDeviceInfo types, and a scale change re-DPIs the Settings window itself mid-click. Bounds are physical pixels (do not mix with DIPs). Brightness and night light on/off go through the bar's `qs.*` backend, not `settings.system.*`.
- Wi-Fi radio, networks in range and the Bluetooth radio/list share the BAR's `qs.*` backend (qs.get / qs.set / qs.wifi.list / qs.wifi.scan / qs.bt.list / qs.bt.watch). The native port needs one backend for bar and Settings. Timings: Wi-Fi scan 6 s, connect 25 s sidecar / 45 s main, VPN connect 70 s.
- Wi-Fi password hygiene is deliberate (stripped from args first, nulled after send, never logged, dry-run XML shows REDACTED). Wi-Fi metered has no API (netsh, sent alone, no pre-selected value). Airplane mode uses the undocumented RadioManagementAPI COM object, proven creatable before the switch is offered.
- Confirm patterns differ: Forget (Wi-Fi) and Remove (Bluetooth device, printer) are inline second-press row states. Network reset (System > Recovery) and Advanced start-up use window.confirm, skipped in test runs. Native needs real ContentDialogs plus the test bypass. Advanced start-up closes open apps with grace 0.
- Power page shows `inForce || mode`, so energy saver can display "Best power efficiency" while the user's choice differs. Hibernate DC can read 0x7fffffff and must show as a custom value, never be silently fixed. There is no public energy-saver switch ("always use" = saverAt 100 trick).
- Sound: per-app devices use raw vtable slots 25-27 (21H2 layout) of an undocumented AudioPolicyConfig; default device/format/enable use IPolicyConfig. The page POLLS every 5 s (it does not use VolumeWatch push); mixer rows and balance sliders are cached so a drag survives the poll; writes re-read after 50 ms.
- Storage cleanup is plan + token (15 min expiry, last 4 kept, single use), deletes only unchanged files, Downloads go to the Recycle Bin, and Downloads / Recycle Bin are never auto-ticked (explicit user rule). Two steps (user, then elevated cleanSystem) merge into one result. Write timeout 600 s, scan progress throttled to 300 ms.
- Input settings must go through SystemParametersInfo with SPIF_UPDATEINIFILE|SPIF_SENDCHANGE (registry alone does not reach the session). Touchpad needs Windows 11 24H2+ SPI_GET/SETTOUCHPADPARAMETERS (rewrite the full 44-byte block after a fresh read). Caret blink broadcasts with a 1000 ms SendMessageTimeout. Swift Pair / discovery writes deliberately send no setting-change broadcast.
- Accessibility key-setting writes read the struct and flip ONLY the one flag (game safety). The contrast-theme call needs 30 s (repaints every window). Magnifier/Narrator are uiAccess and must be started via ShellExecute. Text size previews while dragging and writes only on release.
- Pairing timings: displayPin accepted at once, other ceremonies 60 s per step, 180 s total, main waits 190 s; the typed PIN is never logged. Known quirk: the Search button resets to "Search" on the sidecar's first-pass `done` while the 30 s scan lease keeps running.
- Known gaps worth a decision (parity vs fix): "Add printer" by address can never succeed from the page (no driver picker, the sidecar answers "pick a driver", and the button label is also wrong); discovery-mode choices show raw "default"/"advanced"; the device-settings card is all-or-nothing on one unreadable value.
- Time zone change is NOT elevated (SeTimeZonePrivilege). Regional format change uses kernelbase!NlsUpdateLocale(name, 3) then WM_SETTINGCHANGE "intl". Windows Update HRESULTs never reach the page (mapped to words); a pause extension counts from PauseUpdatesStartTime (35-day max).
- Polling: Power 10 s, Notifications 10 s, Display 15 s (+qs), Sound 5 s, Network Status 8 s, Wi-Fi 5 s, VPN/Dial-up 6 s, Airplane 5 s, Bluetooth radio 5 s with a 30 s `qs.bt.watch` lease, print queue 5 s, Date & time 15 s, Windows Security 30 s, Windows Update 60 s (2 s while a check runs). The kit skips ticks while the window is hidden; a native page needs the same "hidden = no poll" rule.
- Row ids and deep links are contract: old ids (display.brightness, sound.output, power.mode, notifications.dnd, network.wifi, network.status, network.networks, ...) must stay byte-identical. Network and privacy-app row keys are djb2-style hashes of GUID/name/app so ids never carry names.
