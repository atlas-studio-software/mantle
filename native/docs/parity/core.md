## Notes for the port
- The standing rule behind everything in SAFE: a killed Mantle must leave Windows as usable as before. Never hide an Explorer window; only the OS-managed auto-hide flag and an empty window region (with a guard process) are used. The original state is written to `shell-state.json` BEFORE any change (the 2026-09-21 incident cost the user a reboot).
- Restore order matters: cursor clip, taskbar region, app bar, taskbar flag (read back), features' stop(), hotkeys, desktop layer. Keep the order and the 12 s hard stop; a slow quit is a nuisance, a wrong shell is a reboot.
- Crash recovery needs a process OUTSIDE main and OUTSIDE its process tree (supervisor started with `--supervise-detach`); Task Manager "End process tree" must not kill it. One supervisor per main (mutex + lock file), crash loop = 3 in 2 min -> give up and restore.
- Explorer dying kills any window parented in Progman (the desktop layer) with WM_NCDESTROY and no WM_DESTROY (0xc000041d). Natively this is the same hazard class (child of a foreign process's window); keep the guard idea (own the destroy) and the TaskbarCreated re-attach with back-off 1.5/3/5/8/12/20 s.
- The desktop layer must never be shown before it is under the icons: a transparent full-screen window above the apps eats every click. Out of tries = close it, never show it.
- `--live` must be typed; a test instance must never touch the shell, global shortcuts, clipboard, media session or the screen (invisible windows). Keep an equivalent of `--test --profile-name` with its own data dir and lock, or every automated test risks the user's live shell.
- Chords are taken from Windows only while the feature is on, healthy, live and not resting (one coalesced `hotkey` call, 30 ms). Alt+Tab and the Win key live in the sidecar's hook so they keep working if main hangs; a native app must keep the keyboard hook out of the UI thread for the same reason. Windows silently drops low-level hooks on wake: re-install on resume/unlock.
- Held volume keys are one event per repeat; observed keys (never taken) and taken chords are different lists.
- Game rest is a memory promise ("it was taking up too much RAM and made my game stutter"): windows destroyed (not hidden), chords returned, launcher destroyed, working set trimmed; `clips`, `files`, `player` deliberately stay up. Native equivalent: unload surfaces, keep a tiny resident core.
- Keep-ready defaults to OFF for Settings, Task Manager, Files (the user: "i need to save ram"); each opt-in costs ~35-45 MB.
- Pop-ups are re-raised on every show (HWND_TOPMOST then HWND_TOP, no-activate) and verified 60 ms later; Windows lets a hidden topmost window sink. A WinUI window needs the same re-raise + hit-test check.
- The bar is `focusable:false`; clicks give no focus, so the foreground right is passed to the sidecar with AllowSetForegroundWindow at click time. A parked-off-screen window (not hide/show) keeps mouse input and the compositor warm for the switcher and bar. Both are hard to reproduce in WinUI 3 without WS_EX_NOACTIVATE windows and manual z-order control: candidate for a WebView2/Win32-hosted window.
- Outside-click and Esc closing of pop-ups rides the sidecar's low-level mouse hook (armed only while a pop-up is open, 8 s lease renewed 2.5 s); a poll fallback exists; away-closing reads the foreground every 150 ms.
- The launcher/pop-up open path is a last-intent-wins state machine (surface-gate) with a 600 ms same-click window; port it as logic, not per-window ad hoc code.
- The caller guard (only pages under `ui/` get answers; no navigation, no new windows; `open` allow-list; handles must be positive integers) is a security boundary; a native shell with WebView2 surfaces must keep all of it.
- Every state piece has a plain-words `reason`, and every fallback must show state AND reason (the user's no-silent-failures rule); the tray collapses a down sidecar to ONE line. The status object is the shared contract between the shell and every surface.
- Plain-words rewriting of raw codes (HRESULT, errno, .NET type names, WU_E_*) happens in one table shared with pages; a port needs the same table.
- Log hygiene is a feature: scrubbed user/PC/home, 5 MB rotation, repeated failures collapsed; the diagnostic report is paste-safe.
- Restart of a task-started Mantle waits for the scheduled task to leave Running (Task Scheduler ignores a Run while Running); relaunch by `app.relaunch` otherwise. Replace with the native app's own restart that keeps the same guarantees (way back arranged BEFORE quitting).
- Sidecar commands used by this lane: taskbar, appbar, tbhide, edgeclip, traywatch, desktop (attach/recheck/fit/detach), hotkey (winTap/chords/observe/popwatch/rearm), focus, ping/protocol age, gamemode.scan/gamemode.trim, windows, tray (files: sidecar/TaskbarHide.cs, Desktop.cs, Hotkey.cs, AltTab.cs, Supervisor.cs, Lanes.cs).
