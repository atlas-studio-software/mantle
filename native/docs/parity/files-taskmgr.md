## Notes for the port
### Files
- Big folders: the sidecar streams FindFirstFileEx results (first batch <=100 items or 16 ms, then <=1000) and main forwards them untouched; the page virtualises (fixed row heights, binary search over line tops, 240 px overscan). WinUI 3 ItemsRepeater/ListView virtualisation must match 10k-item paint cost and keep selection by key across re-sorts.
- Hidden timings: Reading-state delay ~280-300 ms, progress card 400 ms, search debounce 450 ms, type-ahead 900 ms, submenu hover 160 ms, side-pane refresh 120 ms, thumbnail ask 60 ms after scroll, tab report 300 ms, settings write 800 ms, bounds 700 ms, watcher 250 ms + 200 ms, drop highlight 150 ms, early-opdone hold 3 s, keep-ready spare 4 s, last-file write 1 s.
- Hard natively: the shell context menu ("More") needs one long-lived STA thread with a message pump (shell extensions post messages); FilesShell.cs already does it and native can call it in-process, but must keep the 60 s token model and HIDE_VERBS de-dup.
- Hard natively: thumbnails via IShellItemImageFactory on two STA workers with alpha kept, a disk cache keyed by path|m|s|px|mode and a drop-oldest queue; must not block the UI thread (cold video frames are slow).
- Drag and drop: drag-out uses a real OS drag (Electron startDrag); drop-in always reports DROPEFFECT_COPY to the source so a "move" source never deletes originals before Mantle reads them; Mantle decides move/copy itself (same volume moves, Ctrl/Shift override).
- Windows quirks worked around: sync stat on an unreachable share freezes for the SMB timeout (never stat network/unknown drives on the open path); legacy Path.GetFullPath throws past 260 chars (use GetFullPathNameW + \\?\); saved last folder could be a file (3 of 6 opens failed); acrylic is drawn by DWM only on the active window, so the inactive page goes solid; Windows app mode tints acrylic, so main asks for a light/dark frame (taskmgr.frame) per window.
- Content search and zip are pure node today (_files-grep.js reads Office XML out of the zip container; _files-zip.js writes PKZIP with UTF-8 names, ZIP64, stores already-compressed types, refuses zip-slip). Native needs C# equivalents with the same refusal rules and "no partial output" cleanup.
- Preview pane relies on Chromium for images/video/audio/PDF; WinUI 3 has MediaPlayerElement and Image, but no built-in PDF viewer: a WebView2 (or Windows.Data.Pdf rendering) fallback is the likely port for PDF.
- Undo/redo history is global across windows (30 steps) and built from per-item sidecar results; labels must stay name-free because they reach the log.
- The test guard is two-layer (main + passive sidecar); a native port must keep both the sidecar FilesGuard and an in-process pre-check, and the dry-run behaviour for every app-starting action.
- Sidecar files this surface depends on: sidecar/Files.cs (roots, list, stat, size, search, recent, types, icons, cancel, conflicts), FilesOps.cs (files.op, recycle list/restore/purge/empty), FilesShell.cs (verbs, verb, handlers, openwith, openwithdialog, clip.get/set), FilesThumbs.cs (files.thumbs), FilesNative.cs (shared COM/job table/error words), FilesGuard.cs; plus taskmgr.frame (sidecar/TaskMgr.cs) for the window frame.
- Error text is a single plain-words table shared with lib/plain-error.js (model.js#plainReason); the port must reuse the same table so main and page never disagree.
### Task Manager (shell, Processes, Performance, Game, Settings, guard rules)
- Cadence is driven by Settings `updateSpeed` through `_taskmgr-model.js#tickMs` (front 500/1000/4000 ms, behind other windows at least 3000 ms, Paused 0). The `FOCUSED_MS = 1500` constant and the header comment's "1.5 s focused" are out of date. The header's "Close HIDES it for 3 minutes" is also out of date: close now destroys unless keep ready is on. Port the code, not the comments.
- The Processes list is the hard part for WinUI 3. It is a virtualised, grouped, sortable tree with 300+ rows and children that load on demand (a "Loading..." row). Rows are patched in place by key each tick. Rows freeze while the pointer is over the list, and there is type-ahead, column resize/chooser, heat cells and totals in the header. ItemsRepeater over a flattened list (group header, row and child items) is the likely route. The ~200 KB-per-tick model is why rows are compact; a native port can drop the IPC but should keep the "children only while expanded" rule for CPU.
- Live graphs: up to 60-sample area+line paths per graph, plus one graph per logical processor (grid), four GPU engine graphs and sparklines on every card, all redrawn only when their numbers change. In WinUI use Composition/Win2D path geometry rather than XAML Polyline churn. Graph summary view also hides the rail and title search, so it is a window-level mode.
- Heat colours are `color-mix(accent, n%)` at 5/9/14/20/28% (dark 6/10/15/21/28%). Precompute five brushes per theme and refresh them on accent or theme change.
- Guard rules must move unchanged. Strict path: Free up RAM, game-start free and Trim only go through sidecar `taskmgr.close`/`taskmgr.trim` after `planFree`/`tickWhy`/`actionsFor`. User path: End task, Efficiency and dump on Windows/critical/Mantle processes go through `taskmgr.endpid`/ProcOps with needsConfirm decided BEFORE dryRun. Identity is always pid + creation time.
- Glass: light = DWM acrylic system backdrop (active window only; the frame shade is set by sidecar `taskmgr.frame`, DWMWA dark-mode on its own hwnd). Dark = opaque window with the wallpaper painted under a tint (wall-bdrop). Natively: DesktopAcrylicController for light; dark needs its own wallpaper layer.
- The Settings `theme` (system/light/dark) is saved and validated but nothing applies it; the window follows Mantle's global appearance. Decide whether the native version honours it (Windows does).
- Window memory policy: the user asked to "save ram". No window is kept by default; keep ready makes one hidden window after 60 s once the CPU is under 60%. A game rest destroys it. The last list and memory stay in main for the cold open's first frame (shown within 300 ms).
- Page-local persisted state lives in the renderer's localStorage under `taskmgr.*`: `rail`, `lastView`, `runHistory`, `tbl.processes` (vis/w/sort), `proc.group`, `proc.status2` (and legacy `proc.status`), `proc.res`, `perf.sel/cpuGraph/kernel/gpuGraph/gpuEng/gsv/sumv/hideGraphs`. The native port needs a home for these plus a one-time migration. Main-side settings keys: `tm`, `ticks`, `autoFree`, `lastAuto`, `bounds`.
- Sidecar dependencies (names only): TaskMgr.cs (taskmgr.snapshot, close, trim, cmdline, frame, ConfirmText), TaskMgrDetails.cs (taskmgr.endpid), ProcOps.cs (efficiency, dump, restartexplorer, runtask, properties), ProcDetails.cs (taskmgr.procextra), Perf.cs (taskmgr.perf), PerfGpu.cs (taskmgr.gpu), Layouts.cs (layouts.windows), Desktops.cs (taskview.activate), MenuBar.cs (topbar.window), elevated/Host.cs + elevated/NetTrace.cs (taskmgr.netsample), the shared `icon` verb, and GameMode.cs (the never-touch list that TaskMgr.cs shares).
- Run new task's Browse needs main's file dialog (the sandboxed page cannot read paths). The admin box uses ShellExecute runas, never the admin helper. History is per window (26 entries), not Windows' RunMRU.
- Open file location prefers Mantle Files (app event `mantle-open:files`) and falls back to File Explorer, saying why. Switch to uses `taskview.activate` (restore + focus) and `topbar.window` for minimize/zoom. Both cross into other Mantle features, so the native port needs those seams.
### Task Manager (Details, Services, Startup, Users, App history, admin helper)
- One-dialog rule everywhere: each page sends `dryRun:true` + noConfirm first; main's `needsConfirm` (decided by the sidecar BEFORE dryRun) wins over Windows' ordinary question, never both. Users Sign off / Disconnect ALWAYS get the sidecar's needsConfirm (Users.cs), so in practice the page's own ask() words ("Do you want to continue?", "Are you sure you want to disconnect the selected user(s)?") never show; port the sidecar's words.
- Hidden timings: row outcome lines clear after 15 s (all pages); Services re-read 3 s + a fresh read 1.5 s after a real op; Startup re-read 10 s; SRUM 60 s (90 s timeout); app-history record 60 s open / 5 min closed; helper status cache 3 s; helper idle exit 2 min, no-client exit 30 s, pipe connect deadline 8 s; ETW net trace self-stops after 60 s without a read, retry 30 s; dump timeout 120 s; endPid 12 s; goTo misses give up after 3 renders.
- Admin helper is the hardest port piece: a separate elevated C# 5 exe (sidecar/elevated: Program.cs, Host.cs, Srum.cs, NetTrace.cs, StartupImpact.cs; build.ps1 compiles a curated list incl. ../Json.cs, ../TaskMgr.cs, ProcOps/Services/ProcDetails/Users handlers) reached over a named pipe with a token handshake and client-image allowlist. The native client must reproduce the handshake, image-path allowlist (CheckClientImage roots will change when the client exe changes from Electron/sidecar to the WinUI app), the VERSION/stale check and the scheduled-task install. Program.Version "2" must match sidecar/elevated/VERSION.
- SRUM read copies SRUDB.dat out of a VSS shadow copy with esentutl (/vssrec, then /vss fallback) and opens the copy through esent.dll; seconds long, never inside the UI tick. Metered = WWAN bytes only (user-marked metered Wi-Fi cannot be told apart); tiles always 0.
- Per-app network (Users and Processes) = an ETW real-time session "Mantle.TaskMgr.NetTrace" on Microsoft-Windows-Kernel-Network, payload PID (not header PID); must never orphan the session (stop on start, stop, idle, exit, crash).
- Wait chain uses WCT (advapi32) in ProcOps.cs, first 512 threads; waitTime is shown nowhere (no documented unit). Dump uses dbghelp MiniDumpWriteDump full memory to %TEMP%\<exe>.DMP with a 2 GB free-space floor.
- Properties / Open file location accept only a path Mantle itself read (running process, Details row, startup entry, SRUM row, own history row; case-insensitive), a guard to keep natively. Search online = Bing.
- Startup toggling HKLM entries is NOT possible (startup.set not on the helper allowlist), but the startup page test's mock offers "Set up administrator access" and a needsConfirm for it: the mock is ahead of lib; decide which is the contract before porting.
- Sidecar deps (names only): ProcDetails.cs (taskmgr.details, properties), TaskMgrDetails.cs (taskmgr.endpid), TaskMgr.cs (critical-process confirm words), ProcOps.cs (priority, affinity, affinityget, waitchain, uacvirt, dump, efficiency), TaskMgrSvc.cs (services, service, servicesByPid; Critical list), Users.cs (users, userop), Startup.cs (startup.list/set), StartupMeta.cs (startupmeta, biosSec), Layouts.cs (layouts.windows for Switch to), Elevate.cs (Settings broker, not TM).
- lib/elevate.js + sidecar/ELEVATE.md are the SEPARATE per-action Settings broker (one UAC per action, kinds ok/cancelled/timeout/refused/failed/busy/error, ~95 s limit, 3 s no-re-prompt after "no", shield + "Windows will ask for administrator permission to <does>." UI convention). Task Manager does not use it; its rows belong in the Settings inventory, listed here only so nobody merges the two.
