# Sidecar map: `sidecar/**` as a platform for the native port

Baseline: origin/master 6ca499f (2026-11-06). Inventory by lane native-plan-inv-sidecar. Read-only study: nothing was compiled, run or measured; every number below is quoted from the source or its comments.

Scope: `sidecar/*.cs` (131 files, 74,291 lines), `sidecar/elevated/*.cs` (5 files, 2,410 lines), `sidecar/build.ps1`, `sidecar/elevated/build.ps1`, `README.md`, `ELEVATE.md`, the `test-*.js` names, and (for the protocol and the extra processes) `lib/sidecar.js`, `lib/supervisor.js`, `lib/hook-health.js`.

## 0. Summary

- One exe, `Mantle.Sidecar.exe` (WinExe, 64-bit, .NET Framework 4 `csc.exe`, C# 5), that plays **five roles chosen by argv** (Program.Main): the main sidecar (JSON lines over stdin/stdout), `--taskbar-guard=<pid>`, `--supervise=<main pid>`, `--elevated <request>`, and `--record` / `--rec-probe` / `--rec-standin`. A sixth exe, `mantle.elevated.exe` (sidecar/elevated), is built separately.
- ~399 wire commands: 54 built-ins dispatched by a `switch` in `Program.Run` (test-only verbs not counted) plus **345 feature commands** registered by ~80 `[MantleFeature]` classes through `FeatureTable.Add(name, lane, fn)`. 57 distinct push events.
- Eight lanes (threads): `ui` is the WinForms message-loop thread (also the owner of every hook that is not on its own thread); `capture`, `slow`, `qs`, `scan`, `notif` are STA workers; `audio`, `focus` are MTA workers.
- Reuse classes (files): **pure 101, winrt 15, drawing 7, protocol 4, process 9** (136 files). "pure" here means "logic + P/Invoke/COM, should link as-is"; it includes the 3 UIA files (TrayUia, MenuBar, Emoji) that need the WPF `UIAutomationClient` assemblies, and many files that are pure but only correct on a dedicated thread (see section 8).
- The code assumes in many places that the sidecar is **its own process with a known parent** (`Program.OwnPid`, `Program.ParentPid` = Electron main, `Process.GetProcessesByName("Mantle.Sidecar")`, `Environment.Exit`, `TerminateProcess` self, `Application.Run`). In-process, all of these change meaning (section 8).

Reuse class legend: `pure` logic + P/Invoke/COM; `winrt` needs a WinRT projection change under modern .NET (CsWinRT / `Microsoft.Windows.SDK.NET`); `drawing` System.Drawing / GDI+ / WinForms types are central (works on Windows under modern .NET with `System.Drawing.Common`, but check); `protocol` stdio/JSON plumbing the native app replaces; `process` only meaningful as a separate process.

Column notes for the table: "Commands" lists verbs, `[x]` after a verb is its lane when it is not `slow` (`u` ui, `c` capture, `a` audio, `q` qs, `n` notif, `s` scan); built-in verbs (routed by `Program.Run`, not `Features`) are listed first. "Consumers" are the main non-test callers found by grepping the verb names in `lib/`, `ui/`, `main.js` (indicative: several verbs have generic names such as `close` or `toggle`, so a built-in verb's consumer list is a guess). "Threading" says where the code must run.

## 2. The wire protocol (stdin/stdout JSON lines)

Source of truth: `sidecar/README.md` (Protocol), `Program.cs` (Route/Execute/Emit/StartStdinReader), `Json.cs`, `lib/sidecar.js`.

**Framing.** UTF-8 **without BOM**, one JSON object per line, LF endings, flushed after every line; one write lock (`Program._writeLock`) so replies and events interleave without ever splitting a line. Server-side input cap 16 MB per line (`MaxLineChars`), client-side output cap 4 MB per line (`MAX_LINE_CHARS`).

**Request.** `{"id":<any JSON>,"cmd":"<verb>","ttl":<ms>, ...args}`. `ttl` is the caller's own timeout; absent or <= 0 means "no deadline". `id` numbers come back as integers (`3` not `3.0`).

**Reply.** `{"id":..,"ok":true,"result":{..}}` or `{"id":..,"ok":false,"error":"plain words"}`. Two machine-readable extras for non-failures: `"reason":"expired"` (deadline passed before a lane reached it), `"reason":"busy"` (lane held 1024 waiting), `"reason":"cancelled"` (morph superseded). An unparsable line is answered with `"id":null`. A request line with no `cmd` is `bad request: no cmd field`; an unknown verb is `unknown command: <cmd>`.

**Events.** Lines with `ev` instead of `id`. First line is always `{"ev":"ready","pid","passive","version"}` (version `0.3.0`). The `log` event carries `level` warn/error and plain words. Event names found in the source (57 distinct, the `--record` child's included): `ready, log, restore, hotkey, windows (with iconDiff:true), taskbar, tbhide, edgeclip, tray, topbar, topbarstats, widgethide, underrow, osd, volume, net, battery, media, notifications, notifications.coming, notifications.looks, appchanged, powermode, session, unfold, maxfold, switcher, chord, key, keylate, popwatch, deskmenu, emoji, clip, clips.encoding, clips.encoded, elevate, apppower, btdevices, devpair, files.items, files.size, files.found, files.progress, files.opdone, pingtest, qs, run, sysdisplay, syssound, sysstorage`.

**Conventions.** HWNDs are decimal strings. Rects are physical pixels (the exe is per-monitor-v2 DPI aware; `ping.dpiAware/dpiMode/dpiReason` report it). Integer args clamp to the int range. JSON in is strict (JSON number grammar, `\u` exactly four hex digits, 128 nesting levels). JSON out writes NaN/Infinity as `null`, a lone surrogate as a `\u` escape, and a result that cannot be serialised still answers `ok:false` "the answer could not be written (...)". Error text is always a human sentence; nothing fails silently.

**Handshake/feature detection.** `ping` returns `{pid, passive, version, dpiAware, dpiMode, selfHwnd, commands[], load{lanes[]}, caches, watches{volume,net}, features{commands[], problems[]}}` and `dpiReason` when something was not ideal. `lib/sidecar.js#protocolAge` treats a ping without `dpiAware` as an exe older than the safety protocol and refuses every shell change.

**Client rules (lib/sidecar.js, the contract the native host must keep in spirit).** `CALL_TIMEOUT_MS` 8000 default per call; a call made while starting waits for the ready line up to `READY_WAIT_MS` 8000 (or its own timeout, whichever is shorter) and is then sent with the time it has left as `ttl`; a call with no process is refused at once. Late answers to timed-out ids are remembered (500 ids) and counted, not reported as mysteries. Crash restart: up to `MAX_RESTARTS` 3, delay 3 s doubling (3, 6, 12 s), the budget resets only after `STABLE_MS` 60 s up; `retry()` is the way back after "gave up". Liveness: one `ping` every `HEALTH_MS` 15 s (answers within 3 s, a `busy` reply counts as an answer), 3 misses in a row end the process and take the crash path. stderr is rate-limited to 20 lines per 10 s, each cut to 300 chars. `stop()` ends stdin and kills after 1.5 s. A write to a dead stdin is absorbed by an `error` listener (an unhandled EPIPE used to shut down all of Mantle). `windows` events arrive with `iconDiff:true`; the client rebuilds the full list per hwnd and re-reads the whole list once (4 s) if it missed an icon.

## 3. The dispatcher: Program.cs, Features.cs, Lanes.cs

**Program.Main** order (every step matters): `InitDpi()` first statement (PER_MONITOR_AWARE_V2, falling back to system DPI aware; announced in ping/log), then argv role dispatch (`--taskbar-guard`, `--supervise`, `--elevated`, `--record*` return before anything else runs), parse `--passive`, `--parent-pid`, `--state-file`; `TaskbarHide.Prestart` (spawn the guard, non-passive); stdout writer; `UnhandledException` -> `RequestShutdown`; `Application.ThreadException` (survivable, logs); `SetConsoleCtrlHandler`; create `MsgForm` (hidden `WS_EX_TOOLWINDOW`, never visible) on the main STA thread; `ShellState.CaptureOriginal` (reads ABM state + work area, writes the state note); `WindowList.Start` (read-only, runs in passive too); `Features.Table` (reflection registers every feature + lanes); emit `ready`; report DPI; non-passive stale cleanups (`EdgeClip.ClearStaleAtStartup`, `TaskbarHide.TakeGuardNote/ClearStaleAtStartup`); write state file (or warn "no --state-file"); `Lanes.Start`; `StartStdinReader`; `WatchParent`; `QuickSettings.WarmUp`; `Application.Run(new ApplicationContext())`.

**Request path.** stdin thread `mantle-stdin` (background) reads a capped line, stamps `Stopwatch` arrival, `Route`: parse (errors answered inline, id null), decide `Exempt` (undo), read `ttl`, pick the lane (`Lanes.For`: `sleep` test lane, `_switchArg` for read-vs-switch verbs, `_laneOf` registry, default `ui`), compute coalesce key, post to the lane worker or `BeginInvoke` onto the message loop (ui). `Execute` -> `ExecuteCore`: skips waiters whose `ttl` already passed (reply `expired`), runs `Run(cmd, req, ref result)` once, replies to every coalesced waiter; exceptions map to plain-word errors (`FormatException` -> `bad request:`, `InvalidOperationException` -> its own message, else `command failed: <Type>: <msg>`); a `Deferred` result means the handler will reply itself later (only `morph`).

**Run().** A `switch` over the 54 built-ins (below); anything else falls through to `Features.TryRun`. Test-only verbs (refused outside `--passive`): `sleep {lane,ms}`, `selftest {op}` (echo, unwritable, getint, throw, stateRace, resources), `session {simulate}`, plus per-feature `*.rehearse/lab/simulate/fixture/testclick/testdrop` verbs.

Built-in verb -> file: `windows foreground focus minimize close toggle` Windows.cs/Foreground.cs; `lnk` Shortcuts.cs; `keys` Keys.cs; `hittest raise` HitTest.cs; `traywatch` TrayWatch.cs; `taskbar appbar workarea` Taskbar.cs (+State.cs); `glass` Glass.cs; `corners` Corners.cs; `underrow` UnderRow.cs; `underpaint underhint winproc` UnderPaint.cs; `underwatch` UnderDup.cs; `backdrop` Backdrop.cs; `edgeclip` EdgeClip.cs; `tbhide` TaskbarHide.cs; `morph region place` Morph.cs; `desktop` Desktop.cs; `hotkey` Hotkey.cs; `wifi` Network.cs; `wlan` Wlan.cs; `btdevices` BtDevices.cs; `bluetooth` Bluetooth.cs; `brightness nightlight` Display.cs; `power` Power.cs; `battery` Battery.cs; `volwatch` VolumeWatch.cs; `net` NetState.cs; `qswatch` QuickSettings.cs; `volume` Volume.cs; `audio` AudioMixer.cs; `icon` Icons.cs; `app pins launch` Apps.cs; `tray trayClick` Tray.cs/TrayUia.cs; `media` Media.cs; `notifications` Notifications.cs; `search` Search.cs; `session` Session.cs; `ping quit` Program.cs.

**Features.cs.** `[MantleFeature]` static class with `public static void Register(FeatureTable t)`; `t.Add("feature.verb", lane, fn)` (dot required, lane one of the 7 names, duplicates refused, a throwing Register is recorded in `ping.features.problems` and skipped, never fatal). Handler contract = `Program.Run`: `string fn(Dictionary<string,object> req, ref object result)`: return null with `result` set, or a plain-words error. Writes must refuse in passive themselves (`FeatureTable.PassiveRefusal`). `Features.Event(name, fields)` pushes `{ev:name,...}`. Native note: the registration seam is reflection over the assembly; a native host can keep it (calls become in-process method calls) or replace it with a direct registry.

**Lanes.cs.** Worker lanes (thread, apartment, priority): capture STA AboveNormal; slow STA Normal; audio MTA AboveNormal; qs STA AboveNormal; focus MTA AboveNormal; scan STA AboveNormal; notif STA Normal. Verb-to-lane registry (`_laneOf`): capture = `backdrop underrow underwatch underpaint underhint winproc` + `shot.grab/save/copy/release/ocr/owner`; slow = `icon lnk app pins launch tray trayClick media` + every feature verb not named below; audio = `volume audio osd.volume autopause.peaks`; focus = `focus minimize close toggle`; scan = `gamemode.scan`; notif = `notifications toasts.banners toasts.quiet`; qs = the switch form of `wifi(on) bluetooth(on) brightness(level) nightlight(on)` plus `apppower.status clip.paste gamemode.power gamemode.saver powermode.* snap.move snap.zone sysdisplay.project sysnotify.dndGet`; ui = everything unlisted (hooks, windows, anything latency-critical), including `wlan btdevices search` whose case merely hands off to pool threads. Deadlines, undo exemption (`quit`, `edgeclip off`, `tbhide off`, `taskbar restore`, `appbar remove`, `hotkey` turning a feature off, `desktop detach`, `morph cancel`, `workarea reset`, `topbar.release`, `topbar.watch/stats/guard off`), coalescing (`backdrop`, `underrow` anywhere in the queue; `brightness.set`, `media get`, `notifications list`, `volume.read/level/mute`, `audio.devices/sessions/session.level` tail only), `MaxQueued` 1024 per lane (ui counted separately), "lane held long" log (> 1000 ms, at most one line per lane per 10 s, command name only), hold statistics (goal 500 ms; `ping.load.lanes[].held`; `ping {resetHeld}` passive only), awake-time clock (`QueryUnbiasedInterruptTime`, so a sleep does not look like a hold), and `Cached` (stale-while-revalidate for slow Quick Settings reads: one long-lived refresh thread per cache, `ageMs`/`stale` in the answer, `Put()` after a switch bumps a generation so an older refresh cannot overwrite it).

- Compiler: `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe` (ships with Windows; no SDK, no NuGet, no project file). ## 8. Threading hazards for in-process use

Each item is something that blocks, pumps messages, needs its own STA/thread, or assumes it is alone in its process.

1. **The "ui lane" is the WinForms message loop** (`Application.Run`, `MsgForm`, `BeginInvoke`). It owns the WinEvent hooks, WinForms `Timer`s and `NativeWindow`s of Windows, EdgeClip, TrayWatch, MenuBar, Battery, Unfold, TopbarStats, TaskbarHide. In a WinUI 3 app the UI thread belongs to the dispatcher and the XAML/composition work; hooks installed there compete with rendering, and WinForms `Timer` needs a WinForms-style pump (a WinUI dispatcher pumps Win32 messages, so it may work, but the 250 ms/2 s `Windows` detector, `EdgeClip` settle timers and `TrayWatch` flush timers must be re-hosted on a dedicated message-loop thread to keep ui-lane latency promises).
2. **Low-level hooks need a thread that never stalls.** `Hotkey` (Highest priority thread, microsecond procs), `DeskClick`, `Emoji`, `PopWatch`. Windows silently removes a LL hook whose thread misses `LowLevelHooksTimeout`. In-process, a GC pause or UI hitch in the app must not touch these threads (keep them dedicated, no managed allocation in the proc, avoid workstation-GC blocking); HookHealth's re-arm on wake/unlock is the safety net and must be kept.
3. **STA/MTA apartments are per-lane contracts.** capture/slow/qs/scan/notif are STA (shell links, `SHGetFileInfo`, AppsFolder items, IFileOperation, WMI, WinRT radios proven there), audio/focus MTA (CoreAudio, user32 on foreign windows), Media/Notifications own MTA threads, ClipHistory/FilesShell/FilesThumbs/Screenshot own STA threads with a pump. Blocking one of these on the WinUI STA thread (or `.Wait()`/`.Result` on a WinRT operation from an STA with a pump) risks reentrancy/deadlock; `WinRt.Await` blocks on a `Completed` callback and must stay off the UI thread.
4. **Cross-process calls that can hang on a sick app/Explorer.** `focus`/`minimize`/`close`/`toggle` (AttachThreadInput + ShowWindow measured 5.2 s under a game), `Tray.cs` (`TB_GETBUTTON` + ReadProcessMemory into explorer), `TrayUia`/`MenuBar` (UIA client calls, must not run on a thread that pumps the app's UI), `TaskbarHide` (`SetWindowRgn` on explorer: own thread with a deadline), `SendMessageTimeout` on Progman. They stay on their own lanes/threads; never move them onto the dispatcher.
5. **Process identity is hardcoded.** `Program.OwnPid` / `Program.ParentPid` define "Mantle's own windows" (the `glass corners region morph place raise traywatch appbar desktop` ownership gate, window-list exclusion, AltTab/Desktops/Layouts/MaxFold/GameMode/AppPower self checks). With one process, `ParentPid` is meaningless (WebView2 child processes replace Electron's children). The literal image name `Mantle.Sidecar` is matched in `EdgeClip.ClearStaleAtStartup`, `TaskbarHide.OtherHolder`, `Supervisor` (tracks the sidecar's exit code to detect a tree kill), `TaskMgr` (classifies "mantle"), `GameMode`/`AppPower` never-touch lists. The new exe name must be added or those fail open/closed in the wrong direction.
6. **The restore model assumes the sidecar can die independently.** `SafetyRestore`, `RequestShutdown` -> `Environment.Exit`/`TerminateProcess` self, the 2 s hard-exit watchdog, `SetConsoleCtrlHandler` (never fires for a WinExe), `AppDomain.UnhandledException` waiting `HardExitMs+1000`, and parking the loop thread (`ParkLoopForExit`) are process-level. In-process, any of them kills the whole shell UI. The restore steps must be callable as a function (shutdown, crash handler, WM_ENDSESSION) without exiting, and the taskbar guard, supervisor and banner-restore processes (section 4) must survive as separate processes because a region/registry value/ClipCursor outlives a crash of the new host.
7. **stdout is the protocol today.** Any `Console.Write`, WinForms dialog or exception text that reaches the host is a protocol line; nothing in the sidecar assumes a console. In-process this plumbing (Emit lock, `_suppressEvents` during shutdown, 16 MB cap, `ReplyBusy/Expired`) is replaced by direct calls, but the **semantics** (ttl expiry, coalescing, bounded queues, "busy" instead of unbounded growth, undo-exempt commands) must be kept or the 2026-09-22 failure (a permanently backed-up queue) returns.
8. **DPI.** `InitDpi()` must be the first call before any window, and every rect crossing the protocol is physical pixels (`SHAppBarMessage` is not DPI-virtualised). A WinUI 3 app is per-monitor-v2 by manifest; the callers that divided by Electron's `scaleFactor` change. `Screen`/`SystemInformation` (WinForms) calls in Recorder/EdgeClip/TrayWatch assume that mode.
9. **Windows that the sidecar creates**: the `MsgForm`, hidden `NativeWindow`s (Battery, Unfold, TopbarStats, ClipHistory, Screenshot, AltTabLive), UnderPaint's native painted window (own thread, Highest priority), MaxFold's overlay, Hotkey's raw-input message-only window. Each must live on a thread that pumps and survive the host's own window teardown order.
10. **WinEvent flags.** `WINEVENT_SKIPOWNPROCESS` is used by Windows.cs and Osd.cs; in-process it would also skip the host's own windows (acceptable for the list, wrong for hooks that watch the bar itself: UnderPaint's bar hook passes the bar's pid with flags 0).
11. **Late-bound COM and `dynamic`/reflection.** Volume, AudioMixer, NetState, Desktops (virtual desktop COM), HotCorners, JumpList, Files* and SysUpdate use `Activator.CreateInstance`/`Type.GetTypeFromCLSID` and hand-ordered vtable interfaces ("method order is the ABI"). These compile unchanged but need `System.Runtime.InteropServices` equivalents under trimming/AOT (COM-visible types are not trim-safe).
12. **Memory/handles.** Per-process GDI/USER handle budgets, `Backdrop.Release()` at exit and a 150-round handle-count test (`test-protocol.js`) assume a small helper process. The host now shares the handle budget with XAML.
13. **Elevation re-launches the same exe.** `Elevate` starts `this exe --elevated`, and the Supervisor restarts main from the recorded exe/args/cwd. Both need a CLI mode on the native exe (or a retained small helper exe).
14. **Reflection scan.** `Features.Table` enumerates `typeof(Features).Assembly.GetTypes()`; with trimming or ReadyToRun this needs explicit registration (preserve attributes).
